    Misión 1

    El navegador y sus DevTools

    Tu microscopio: con él verás qué pasa dentro de cualquier web, incluida la tuya.

    Correspondencias ↗La petición↗Lighthouse

    Las cinco pestañas que vas a usar

    Usa Chrome, Edge o Firefox actualizados. Las DevTools (herramientas de desarrollo) se abren con F12 o con Ctrl+Mayús+I.

    PestañaPara qué te sirve en este bloque
    Elements (Elementos)Ver el HTML y el CSS de lo que hay en pantalla. Ya la conoces.
    Console (Consola)Ver los errores. Si tu web no guarda en Supabase, el motivo aparece aquí en rojo.
    Network (Red)Ver cada petición: a dónde va, qué código devuelve (200, 404…) y cuánto tarda.
    Application (Aplicación)Ver lo que la web guarda en el navegador (almacenamiento local, cookies, la sesión de Supabase).
    LighthouseAuditar rendimiento, accesibilidad y SEO de tu web publicada.
    Misión 110 minutos
    1. Actualiza tu navegador: menú ⋮ → Ayuda → Información (en Chrome o Edge). Se actualiza solo y te pide reiniciarlo.
    2. Abre esta misma página, pulsa F12 y coloca las DevTools abajo o a la derecha (menú ⋮ de las DevTools → Dock side).
    3. Ve a la pestaña Network, marca Disable cache y recarga con F5. Verás aparecer la lista de peticiones.
    4. Busca la petición metro.css: pulsa en ella y mira la pestaña Headers: Status Code debe ser 200.
    5. Ve a Console. Si está vacía o solo hay avisos grises, la página no tiene errores.

    Comprueba: sabes abrir las DevTools, encontrar una petición en Network y leer su código de estado. Es la habilidad que más tiempo te ahorrará en la página 08.

    Si algo falla
    F12 no hace nada
    En algunos portátiles hay que pulsar Fn+F12. Usa Ctrl+Mayús+I.
    La pestaña Network está vacía
    Solo registra lo que pasa con ella abierta: recarga la página con las DevTools abiertas.
    Las DevTools están en inglés
    Es lo normal y lo que verás en tutoriales. Si prefieres castellano: ⚙ Settings → Preferences → Language.

    Misión 2

    Visual Studio Code a punto

    Ya lo usas desde el primer bloque. Ahora lo afinamos para trabajar con proyectos reales.

    Correspondencias ↗localhost y Live Server

    Extensiones recomendadas

    Se instalan desde el icono de los cuadraditos de la barra izquierda (Ctrl+Mayús+X), buscando el nombre y pulsando Install.

    ExtensiónQué hace¿Obligatoria?
    Live ServerTu servidor local en 127.0.0.1:5500, que recarga al guardar.Sí (ya la tienes)
    Prettier · Code formatterOrdena y sangra tu código al guardar.Muy recomendable
    Error LensMuestra los errores escritos en la misma línea donde están.Recomendable
    Spanish - Code Spell CheckerMarca faltas de ortografía en tus textos (instala también «Code Spell Checker»).Recomendable
    DotENVColorea los archivos .env.Opcional
    Misión 210 minutos
    1. Actualiza VS Code: Help → Check for Updates (en castellano, Ayuda → Buscar actualizaciones).
    2. Instala Prettier y Error Lens (y, si quieres, el corrector en castellano).
    3. Activa el formateo al guardar: Ctrl+, → busca format on save → marca Editor: Format On Save.
    4. Activa el guardado automático: menú File → Auto Save. Así Live Server recarga sin que pulses Ctrl+S.
    5. Abre la terminal integrada con Ctrl+ñ (en teclado español) o desde Terminal → New Terminal. La usarás en la parte opcional de Node.js.

    Comprueba: escribe un HTML mal sangrado, guarda, y Prettier lo ordena solo. En la esquina inferior derecha ves Go Live (Live Server).

    Si algo falla
    Prettier no formatea al guardar
    Clic derecho en el código → Format Document With… → Configure Default Formatter → Prettier.
    No aparece «Go Live»
    Abre una carpeta (File → Open Folder), no un archivo suelto. Live Server necesita una carpeta abierta.

    Misión 3

    La carpeta del proyecto

    El libro de visitas que crecerá a lo largo del manual. Empieza ordenado y seguirá ordenado.

    Correspondencias ↗index.html y carpetas↗Secretos

    La estructura

    • README.md: la portada del repositorio en GitHub. Explica qué es el proyecto, cómo verlo en local y dónde está publicado. Se escribe en Markdown (texto con # para títulos y - para listas).
    • .env.example: una plantilla con los nombres de las variables, sin los valores. Así, quien descargue el proyecto sabe qué necesita. El .env real (con valores) no se sube nunca.
    • .gitignore: la lista de archivos que Git debe ignorar. Lo usarás de verdad en el bloque 09, pero déjalo creado desde hoy.
    Misión 310 minutos
    1. Crea en tu ordenador una carpeta libro-de-visitas (minúsculas, sin espacios ni tildes) en un sitio fácil de encontrar, como Documentos/proyectos/.
    2. Ábrela en VS Code: File → Open Folder.
    3. Crea las carpetas css, js e img con el icono de «nueva carpeta» del explorador de VS Code.
    4. Crea los archivos vacíos index.html, privacidad.html, css/estilos.css, js/config.js, js/app.js y README.md.
    5. Crea .env.example y .gitignore y pega en ellos el contenido de las cajas de arriba (los nombres empiezan por punto: es correcto).
    6. En index.html escribe ! y pulsa Tab para la estructura básica; cambia lang="en" por lang="es" y pon un <h1>. Pulsa Go Live.

    Comprueba: el navegador abre http://127.0.0.1:5500/index.html con tu título y el explorador de VS Code muestra exactamente la estructura de arriba.

    Si algo falla
    Windows no me deja crear un archivo que empieza por punto
    Créalo desde VS Code, no desde el explorador de Windows: VS Code lo permite sin problema.
    No veo .gitignore en el explorador de Windows
    Los archivos que empiezan por punto se tratan como ocultos. En VS Code se ven siempre.

    Misión 4

    Contraseñas y doble verificación

    Vas a manejar tres cuentas con acceso a tu web y a tus datos. Si te roban una, te roban la web.

    Correspondencias ↗Secretos↗Seguridad y ley

    Dos herramientas, cinco minutos cada una

    • Gestor de contraseñas: una caja fuerte cifrada que recuerda todas tus contraseñas y claves; tú solo recuerdas una. Opciones gratuitas: Bitwarden (multiplataforma), el gestor de tu navegador o el del móvil. Aquí guardarás la contraseña de la base de datos de Supabase (página 04).
    • Verificación en dos pasos (2FA): además de la contraseña, un código de 6 cifras que genera una app del móvil (Google Authenticator, Microsoft Authenticator, Aegis…) o una llave de acceso (passkey). Aunque alguien sepa tu contraseña, sin tu móvil no entra.
    Muy importante

    Al activar la 2FA, cada servicio te da unos códigos de recuperación. Guárdalos en el gestor de contraseñas. Si pierdes el móvil sin ellos, puedes perder la cuenta para siempre.

    Misión 410 minutos
    1. Instala un gestor de contraseñas (por ejemplo, Bitwarden: extensión del navegador y app del móvil) y crea una contraseña maestra larga: una frase de cuatro o cinco palabras.
    2. Instala en el móvil una app de autenticación (Google Authenticator, Microsoft Authenticator o similar).
    3. Crea en el gestor una carpeta o etiqueta «libro-de-visitas»: ahí irá todo lo del proyecto.

    Comprueba: el gestor rellena una contraseña en una web de prueba y la app del móvil está instalada. La usarás en la misión siguiente.

    Misión 5

    Cuentas: GitHub, Vercel y Supabase

    Una cuenta principal (GitHub) y las otras dos entrando con ella. Menos contraseñas y todo conectado.

    Correspondencias ↗02 · Publica tu web↗Supabase

    Por qué en este orden

    GitHub es la cuenta «madre»: Vercel y Supabase permiten entrar con Continue with GitHub. Así, si proteges bien GitHub (2FA), proteges las tres, y Vercel puede leer tus repositorios para publicarlos solo. El paso a paso de GitHub y Vercel está en la página 02 (y, con pantallas ilustradas, en Súbela a internet); aquí solo creamos y aseguramos las cuentas.

    Misión 515 minutos
    1. Crea tu cuenta en github.com (si no la tienes) con un nombre de usuario profesional en minúsculas. Guarda la contraseña en el gestor.
    2. Activa la 2FA en GitHub: foto de perfil → Settings → Password and authentication → Enable two-factor authentication. Escanea el código QR con la app del móvil y guarda los códigos de recuperación en el gestor.
    3. Entra en vercel.com → Sign Up, elige el plan Hobby y pulsa Continue with GitHub.
    4. Entra en supabase.com → Start your project y pulsa Continue with GitHub.
    5. En Supabase, activa la 2FA en tu cuenta: avatar → Account preferences → Security (o «Multi-factor authentication»).
    6. Apunta en el gestor qué cuenta usas en cada servicio: así nunca dudarás con qué entrar.

    Comprueba: puedes entrar en Vercel y en Supabase con el botón de GitHub, y GitHub te pide el código del móvil al entrar desde otro navegador.

    Si algo falla
    Vercel o Supabase no me dejan entrar con GitHub
    Comprueba que tu correo de GitHub está verificado (GitHub → Settings → Emails).
    El nombre de los menús no coincide
    Los servicios cambian su diseño a menudo. Busca siempre las mismas palabras: Security, Two-factor, Account.
    No tengo móvil propio
    Las passkeys (llaves de acceso del propio ordenador) o una llave física de seguridad sustituyen a la app. Pregunta a tu profesor si el centro ofrece una alternativa.

    Misión 6 · opcional

    Node.js y la terminal

    No lo necesitas para el manual, pero abre la puerta a las herramientas profesionales.

    Correspondencias ↗Supabase en local↗Funciones

    Qué son Node.js y npm

    Node.js permite ejecutar JavaScript fuera del navegador, en tu ordenador. Con él viene npm, el gestor de paquetes: una tienda gigante de herramientas que se instalan con una orden. Las usarás en el bloque NPM y en el de JavaScript, pero ya puedes probar dos:

    • npx vercel: publicar en Vercel desde la terminal.
    • npx supabase: la herramienta de Supabase (proyectos en local, migraciones…).

    npx descarga la herramienta y la ejecuta sin instalarla para siempre.

    Misión 610 minutos · opcional
    1. Descarga la versión LTS (soporte largo, la estable) desde nodejs.org e instálala con las opciones por defecto.
    2. Cierra y vuelve a abrir VS Code, abre la terminal (Ctrl+ñ) y escribe node -v: debe salir un número de versión.
    3. Escribe npm -v: también debe salir un número.
    Si algo falla
    «node» no se reconoce como un comando
    Cierra del todo VS Code (y la terminal) y vuelve a abrirlo: la terminal necesita recargar las rutas del sistema tras instalar.
    En PowerShell sale un error de «ejecución de scripts deshabilitada» con npx
    Usa la terminal Command Prompt o Git Bash en VS Code (flechita junto al + de la terminal). En ordenadores del centro, pregunta al profesor antes de cambiar políticas del sistema.
