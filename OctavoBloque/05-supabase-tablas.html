    Antes de tocar el panel

    Diseñar antes de crear

    Del formulario a la tabla: cada campo es una columna.

    Correspondencias ↗Formularios HTML↗El plano · tablas

    Cuatro preguntas de diseño

    1. ¿Qué guardo? Una tabla por «cosa»: mensajes, temas, inscripciones.
    2. ¿Qué datos tiene cada cosa? Los campos del formulario + los que pone el sistema (id, created_at).
    3. ¿De qué tipo es cada dato? Texto, número, fecha, sí/no… (sección 2).
    4. ¿Qué reglas cumple? Obligatorio o no, longitud máxima, valores permitidos, único.

    Normas para los nombres

    • Minúsculas, sin espacios ni tildes ni eñes: fecha_nacimiento, no Fecha de nacimiento.
    • Palabras separadas por guion bajo (snake_case): es la costumbre en bases de datos.
    • Tablas en plural (mensajes), columnas en singular (nombre).
    • El nombre de la columna igual que el name del campo del formulario: así, en la página 08, los datos encajan solos.

    Herramienta: del formulario a la tabla

    Escribe los campos de tu formulario y obtén el SQL de la tabla, con sus reglas. Sirve para cualquier proyecto (inscripciones, pedidos, encuestas…).

    Opciones de cada columna en el Table Editor

    • Primary key: el identificador único de la fila. Ya viene en id.
    • Default value: el valor si no se envía nada. Ejemplos: now() (ahora), true, gen_random_uuid().
    • Is Nullable: si se permite vacío (null). Desmárcalo en los obligatorios.
    • Is Unique: que no se repita (un correo por inscripción, por ejemplo).
    • Check constraint: una regla propia, como «entre 2 y 60 letras». Solo con SQL o en las opciones avanzadas.
    Validar dos veces

    Las reglas de la tabla repiten lo que hace el formulario con required y maxlength. La del formulario es comodidad; la de la base de datos es la que de verdad protege, porque el HTML se puede saltar.

    Misión 1

    Crear la tabla con el Table Editor

    La tabla mensajes del libro de visitas, sin escribir código.

    Correspondencias ↗RLS
    Misión 110 minutos
    1. En tu proyecto de pruebas: Table Editor → New table.
    2. Name: mensajes. Description: «Mensajes del libro de visitas».
    3. Comprueba que Enable Row Level Security (RLS) está marcado. Déjalo así siempre.
    4. Ya vienen id (int8, primary key) y created_at (timestamptz, default now()). No los toques.
    5. Add column: nombre, tipo text, desmarca Is Nullable (obligatorio).
    6. Add column: mensaje, tipo text, desmarca Is Nullable.
    7. Pulsa Save.

    Comprueba: en el Table Editor aparece mensajes con cuatro columnas y la etiqueta de RLS activado. Arriba se ve un aviso tipo «RLS enabled, no policies»: es correcto; las reglas llegan en la página 07.

    Si algo falla
    Me equivoqué de nombre o de tipo
    En la tabla, menú de la columna (flecha junto al nombre) → Edit column. Para la tabla entera: menú ⋯ junto a su nombre → Edit table.
    Desmarqué RLS sin querer
    Edit table → vuelve a marcar Enable Row Level Security.

    Misión 2

    Trabajar con filas

    Como en una hoja de cálculo, pero con reglas.

    Misión 210 minutos
    1. Insert → Insert row: escribe un nombre y un mensaje (deja id y created_at vacíos: se rellenan solos) y Save.
    2. Añade tres filas más con nombres distintos.
    3. Prueba una regla: inserta una fila con el nombre vacío. Supabase debe rechazarla (es obligatorio).
    4. Edita un mensaje con doble clic en la celda; pulsa Intro para guardar.
    5. Ordena por created_at con Sort y filtra con Filter (por ejemplo, nombre es igual a uno de tus nombres).
    6. Borra una fila: márcala con la casilla de la izquierda → Delete 1 row.

    Comprueba: tienes tres filas, cada una con su id y su fecha automática, y la fila sin nombre no se pudo guardar.

    Misión 3

    Relacionar tablas

    Cada mensaje pertenece a un tema: una relación «uno a muchos».

    Por qué no escribir el tema en cada mensaje

    Podrías guardar el texto «Felicitación» en cada mensaje. Pero si mañana lo cambias a «Felicitaciones», tendrías que editar cien filas, y alguien escribiría «felicitacion» sin tilde. Lo profesional es una tabla temas con cada tema una sola vez, y en mensajes una columna tema_id que apunta al tema. Esa columna se llama clave foránea (foreign key).

    temasid · int8 🔑
    nombre · text
    mensajesid · int8 🔑
    created_at · timestamptz
    nombre · text
    mensaje · text
    tema_id · int8 → temas.id
    🗂️

    Es el número de mesa de un restaurante: el pedido no copia la mesa entera, solo dice «mesa 4». Si cambias el mantel de la mesa 4, cambia para todos los pedidos.

    Misión 310 minutos
    1. Crea la tabla temas (RLS marcado) con la columna nombre (text, no nullable, Is Unique).
    2. Inserta tres filas: «Felicitación», «Sugerencia», «Saludo».
    3. En mensajes, Add column: tema_id, tipo int8, y pulsa Add foreign key relation (el icono de enlace): tabla temas, columna id.
    4. En la acción al borrar (On delete), elige Set null: si se borra un tema, los mensajes se quedan sin tema en vez de desaparecer.
    5. Edita tus mensajes y asigna a cada uno un tema_id: al pulsar la celda, Supabase te deja elegir de la lista de temas.

    Comprueba: en mensajes, la columna tema_id muestra un icono de enlace, y al pasar por una celda ves a qué tema apunta. En la página 06 los juntarás con JOIN.

    Misión 4

    Importar y exportar CSV

    Meter datos en bloque desde una hoja de cálculo y hacer copias de seguridad.

    Correspondencias ↗Copias de seguridad

    CSV es una tabla en texto: cada línea es una fila y las columnas van separadas por comas. Lo exportan Excel, Google Sheets y LibreOffice. La primera línea debe tener los nombres exactos de las columnas.

    Misión 45 minutos
    1. Crea en VS Code un archivo temas-extra.csv con el contenido de arriba (fuera de la carpeta del proyecto, o bórralo después).
    2. En temas: Insert → Import data from CSV, arrastra el archivo, revisa la vista previa y pulsa Import data.
    3. Exporta mensajes: botón Export (o menú ⋯ de la tabla) → Export to CSV. Ábrelo con tu hoja de cálculo.

    Comprueba: temas tiene seis filas y en tu carpeta de descargas hay un mensajes.csv. Esa exportación es tu copia de seguridad casera (el plan gratis no hace copias automáticas).

    Misión 5

    Lo mismo, con SQL

    Un script que crea todo de golpe: lo usarás para montar el proyecto de producción en segundos.

    Correspondencias ↗Aprender SQL↗Producción

    Por qué SQL además de botones

    Los botones son cómodos, pero no dejan rastro. Un script SQL es una receta guardada: lo puedes repetir en otro proyecto (el de producción), compartirlo con tu equipo o guardarlo en el repositorio. Así trabajan los equipos profesionales.

    Misión 510 minutos
    1. Abre SQL Editor → New query.
    2. Pega el script, ponle nombre (icono de lápiz junto a «Untitled query»): «Estructura libro de visitas».
    3. Pulsa Run (o Ctrl+Intro). Como usa if not exists y on conflict do nothing, no rompe lo que ya creaste con botones.
    4. Guarda también una copia del script en tu carpeta del proyecto: supabase/estructura.sql.

    Comprueba: abajo aparece «Success. No rows returned». En la lista de consultas guardadas está «Estructura libro de visitas» y en tu carpeta, supabase/estructura.sql.

    Si algo falla
    «relation "temas" already exists»
    Te falta el if not exists: copia el script completo de arriba.
    «column "tema_id" of relation "mensajes" does not exist»
    Tu tabla mensajes se creó antes sin esa columna. Añádela: alter table public.mensajes add column tema_id bigint references public.temas (id) on delete set null;
    Un aviso dice que la consulta es destructiva
    Supabase avisa antes de ejecutar drop o delete. Lee siempre qué vas a borrar antes de confirmar.
