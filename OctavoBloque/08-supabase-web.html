tu web

El momento en que todo encaja: tu formulario guarda en Supabase y la lista muestra los mensajes de verdad. Escribirás cuatro archivos, los probarás en tu ordenador, aprenderás a encontrar cualquier fallo con las DevTools y lo publicarás. El JavaScript va completo y explicado: no necesitas dominarlo todavía (eso es el bloque 10), solo entender qué hace cada parte.

    El plan

    Lo que vas a construir

    Cuatro archivos y un viaje de ida y vuelta a Supabase.

    Correspondencias ↗Tu carpeta↗De SQL a la web
    index.htmlLa estructura

    Formulario (nombre, tema, mensaje) y lista de mensajes.

    css/estilos.cssEl aspecto

    Lo que ya sabes hacer, con estados de envío y error.

    js/config.jsLa dirección y la llave

    URL del proyecto y clave publicable.

    js/app.jsEl mensajero

    Lee los temas y los mensajes, y guarda los nuevos.

    El orden de carga importa: primero la librería de Supabase (desde una CDN), luego config.js y por último app.js, que usa lo que definen los dos anteriores.

    1

    Misión 1

    El HTML y el CSS

    Lo que ya dominas. Fíjate en los name: coinciden con las columnas.

    Correspondencias ↗Formularios con CSS↗name = columna

    El libro de visitas (aspecto, todavía sin datos reales)

    El recuadro enseña el diseño con dos mensajes de ejemplo. Los reales llegarán cuando añadas config.js y app.js.

    Misión 115 minutos
    1. En tu index.html, dentro del <body>, pega el HTML de arriba; borra los dos <li> de ejemplo (los mensajes vendrán de Supabase).
    2. En el <head> enlaza el CSS: <link rel="stylesheet" href="css/estilos.css"> y pon un <title> y una meta description.
    3. Pega el CSS en css/estilos.css.
    4. Abre con Go Live: ves el formulario y la lista vacía.
    2

    Misión 2

    La conexión: librería y claves

    Dos etiquetas <script> y un archivo con la dirección y la llave publicable.

    Correspondencias ↗URL y claves↗Por qué la publicable puede ir aquí
    Doble comprobación

    Antes de guardar, mira que la clave empieza por sb_publishable_. Si empieza por sb_secret_, para: estás pegando la secreta.

    Misión 25 minutos
    1. Pega las tres etiquetas <script> al final de index.html, antes de </body>, en ese orden.
    2. Rellena js/config.js con tu URL y tu clave publicable (las tienes en tu gestor, página 04).
    3. Recarga, abre las DevTools → Console y escribe supabase + Intro: debe salir un objeto (la librería está cargada).
    3

    Misión 3

    El mensajero: leer y escribir

    El archivo app.js completo, y su explicación en castellano.

    Correspondencias ↗select, insert, order↗Las reglas que lo permiten

    Qué hace cada bloque

    1. Conectar: crea el cliente de Supabase con tu URL y tu clave. A partir de aquí, db es tu proyecto.
    2. Piezas: guarda en variables los elementos del HTML por su id.
    3. Avisar: escribe un texto en el párrafo de estado y le pone un data-tipo que el CSS colorea.
    4. Temas: select("id, nombre") en la tabla temas, ordenados, y crea un <option> por cada uno. Es el SELECT … ORDER BY de la página 06.
    5. Crear mensaje: fabrica el HTML de cada mensaje con textContent, nunca con innerHTML: si alguien escribe código como mensaje, se muestra como texto y no se ejecuta.
    6. Leer: select con temas(nombre) (el JOIN de la página 06), del más nuevo al más viejo, máximo 50. Mientras carga, la lista lleva aria-busy.
    7. Guardar: preventDefault evita la recarga; FormData recoge los campos por su name; el tema vacío se convierte en null; el botón se bloquea para evitar dobles envíos; insert guarda, y si va bien vacía el formulario y recarga la lista.
    8. Arrancar: al abrir la página carga temas y mensajes.

    Fíjate en el patrón que se repite: const { data, error } = await …. Supabase siempre devuelve dos cosas: los datos o un error. Siempre se mira el error primero.

    Misión 315 minutos
    1. Pega el código en js/app.js y guarda.
    2. Recarga la página: el desplegable de temas se llena y aparecen los mensajes que creaste en la página 05.
    3. Firma el libro con tu nombre: sale «¡Gracias por firmar!» y tu mensaje aparece arriba de la lista.
    4. Abre el Table Editor de Supabase y comprueba que tu mensaje está en la tabla.

    Comprueba: el mensaje que escribes en tu web aparece en el Table Editor, y una fila que añades en el Table Editor aparece en la web al recargar. La ida y la vuelta funcionan.

    4

    Misión 4

    Probar como un profesional

    No basta con que funcione una vez: prueba los casos raros.

    Misión 410 minutos
    1. Network: recarga con las DevTools abiertas y filtra por supabase. Verás GET …/rest/v1/temas y …/mensajes con código 200.
    2. Firma de nuevo y busca la petición POST …/rest/v1/mensajes: código 201 (Created).
    3. Escribe un mensaje con <b>hola</b>: debe verse tal cual, con los símbolos, no en negrita.
    4. Quita el maxlength del textarea con las DevTools (Elements) y envía un texto de más de 500 caracteres: Supabase lo rechaza por la regla check de la tabla.
    5. Prueba la web en modo móvil (DevTools → icono de móvil) y con el teclado (Tab hasta el botón y Intro).

    Comprueba: peticiones con 200 y 201, el HTML escrito por la gente se ve como texto y el texto demasiado largo se rechaza en el servidor aunque se salte el formulario. Tu web es segura aunque alguien la manipule.

    Cuando algo falla

    Guía de depuración

    El 95 % de los fallos están en esta tabla. Mira primero la Console y la Network.

    Correspondencias ↗Códigos de estado↗Probar reglas
    Lo que vesCausaSolución
    supabase is not definedNo se cargó la librería o va después de app.js.Revisa el orden de los tres <script> y tu conexión a internet.
    SUPABASE_URL is not definedconfig.js no se cargó (ruta mal escrita) o va después.Ruta js/config.js exacta, en minúsculas, antes de app.js.
    Invalid API key · 401Clave mal copiada, incompleta o revocada.Vuelve a copiarla de Project Settings → API Keys.
    Failed to fetch · ERR_NAME_NOT_RESOLVEDURL del proyecto mal escrita, o sin internet.Copia la Project URL exacta.
    503 o fallo de conexión de golpeProyecto pausado por inactividad.Panel → reanudar el proyecto (página 04).
    La lista sale vacía, sin erroresFalta la regla de SELECT: RLS devuelve vacío, no error.Página 07, misión 2.
    new row violates row-level security policyFalta la regla de INSERT para anon.Página 07, misión 2.

    Could not find the table … in the schema cacheNombre de tabla mal escrito, o la tabla no está expuesta en la Data API.Revisa el nombre; página 04, misión 4.

    Misión 5 · opcional

    Mensajes en tiempo real

    Que un mensaje nuevo aparezca solo, sin recargar, en todas las pantallas abiertas.

    Misión 510 minutos · opcional
    1. Activa el tiempo real en la tabla: Table Editor → mensajes → botón Realtime (o Enable Realtime). También está en Database → Publications → supabase_realtime.
    2. Añade el código al final de app.js.
    3. Abre tu web en dos ventanas, una al lado de la otra. Firma en una: el mensaje aparece en la otra sin recargar.

    Misión 6 · opcional

    Iniciar sesión con enlace mágico

    Para el libro «con usuarios» de la página 07: solo firma quien ha entrado.

    Correspondencias ↗Direcciones permitidas↗Reglas por usuario

    La dirección de vuelta (emailRedirectTo) debe estar en la lista de Redirect URLs de la página 07. Si no, el enlace del correo te llevará a la Site URL.

    Misión 620 minutos · opcional
    1. Aplica en Supabase el script «con usuarios» de la página 07 (misión 6).
    2. Añade el HTML encima del formulario y el código al final de app.js.
    3. Pide el enlace con tu correo, pulsa el enlace del correo y vuelve a tu web con la sesión iniciada.
    4. Firma: en el Table Editor, tu mensaje lleva tu identificador en la columna autor.

    Misión 7

    Publícalo

    Lo que funciona en local, a internet. Con dos comprobaciones extra.

    Correspondencias ↗02 · Publica tu web↗De cero a producción
    Misión 715 minutos
    1. Revisa que en tu carpeta no hay ninguna clave secreta (busca sb_secret con Ctrl+Mayús+F en VS Code: no debe salir nada).
    2. Sube los archivos a tu repositorio de GitHub (como en la página 02). config.js sí se sube: solo tiene la clave publicable.
    3. Importa el repositorio en Vercel (Framework Preset: Other) y despliega.
    4. Copia tu dirección …vercel.app y ponla en Supabase → Authentication → URL Configuration (Site URL y Redirect URLs).
    5. Abre tu web publicada, firma y comprueba en el Table Editor que llega.

    Comprueba: desde el móvil, en tu dirección .vercel.app, puedes firmar y ver los mensajes. ¡Tienes una aplicación web completa en producción!
