04 · Supabase:
puesta en marcha

Supabase no se instala: es un servicio en la nube. «Ponerlo en marcha» es crear tu proyecto, conocer su panel y guardar a buen recaudo sus datos de acceso.     Antes de empezar

    Qué es Supabase y qué trae

    Un backend completo que se alquila: base de datos, usuarios, archivos y reglas de acceso.

    Correspondencias ↗El plano · Supabase↗Arquitecturas↗Plan gratis

    Lo esencial en un minuto

    Cada proyecto de Supabase es una base de datos PostgreSQL con un montón de servicios alrededor: una API automática para leer y escribir desde la web, un sistema de usuarios (Auth), un almacén de archivos (Storage), reglas por fila (RLS), tiempo real y funciones. Todo se maneja desde un panel web (el dashboard) con botones.

    El plan gratuito permite 2 proyectos activos, 500 MB de base de datos y 1 GB de archivos, y pausa el proyecto tras una semana sin uso (datos y detalles en el plano).

    La unidad Supabase: cinco partes, una red

    Supabase se aprende en cinco paradas, cada una pensada para una sesión. Pulsa cualquier estación para ir a ella; el anillo de cada una se llena con tus pasos marcados.

    ¿Instalar?

    No hay nada que instalar para usarlo: todo vive en la nube y se maneja desde el navegador. Existe una versión para tu ordenador (sección 7), pero es para usuarios avanzados y no la necesitas.

    Misión 1

    Organización y proyecto

    Cinco minutos de formulario y dos de espera.

    Correspondencias ↗Tu cuenta↗Datos en la UE

    Pantalla a pantalla (simulado)

    Las pantallas imitan el panel de Supabase. Lo que importa en cada paso late. Supabase cambia el diseño a menudo: guíate por las palabras.

    Misión 110 minutos
    1. Entra en supabase.com/dashboard con Continue with GitHub.
    2. Crea una organización (Organization) con tu nombre o el de la clase, tipo Personal o Educational, plan Free.
    3. Pulsa New project. Nombre: libro-de-visitas-pruebas.
    4. En Database password pulsa Generate a password, cópiala y guárdala en tu gestor en la carpeta «libro-de-visitas» antes de seguir.
    5. En Region elige una de la Unión Europea (por ejemplo Central EU (Frankfurt) o West EU (Ireland)).
    6. Pulsa Create new project y espera a que termine de prepararse (uno o dos minutos).

    Comprueba: ves el panel de tu proyecto con el menú lateral y, arriba, el nombre libro-de-visitas-pruebas. La contraseña está en tu gestor.

    Si algo falla
    «You have reached the maximum number of free projects»
    Ya tienes dos proyectos gratuitos activos. Pausa o borra uno que no uses (Project Settings → General → Pause / Delete project).
    No guardé la contraseña de la base de datos
    No pasa nada grave: se puede cambiar en Project Settings → Database → Reset database password. Esta vez, guárdala.
    ¿Qué región elijo?
    La más cercana a tus visitantes dentro de la UE. No se puede cambiar después sin crear otro proyecto.

    Misión 3

    La URL y las claves

    Tres datos que conectan tu web con tu proyecto. Uno de ellos jamás debe salir del panel.

    Correspondencias ↗Secretos↗RLS↗Conecta tu web

    Dónde están y qué hacer con cada uno

    En Project Settings → API Keys o en el botón Connect de la parte superior del panel.

    DatoAspecto¿Público?Dónde va
    Project URLhttps://abcd….supabase.coSíjs/config.js de tu web
    Publishable keysb_publishable_…Sí: la protegen las reglas RLSjs/config.js de tu web
    Secret keysb_secret_…No. Se salta todas las reglasEn ningún sitio, salvo una variable de entorno de una función del servidor
    Contraseña de la base de datosLa que generasteNoSolo en tu gestor
    Claves antiguas

    Si ves anon y service_role (textos larguísimos que empiezan por eyJ), son las versiones antiguas de la publicable y la secreta. Supabase las retira a finales de 2026: usa siempre las nuevas.

    Misión 35 minutos
    1. Abre Project Settings → API Keys (o el botón Connect).
    2. Copia la Project URL y la Publishable key en una nota de tu gestor llamada «Supabase · pruebas».
    3. Abre .env.example de tu carpeta y comprueba que los nombres coinciden: SUPABASE_URL y SUPABASE_PUBLISHABLE_KEY. No pegues valores en ese archivo.
    4. No copies la Secret key a ningún sitio. Si algún día se filtra: API Keys → menú ⋯ de la clave → Revoke y crea otra.

    Comprueba: en tu gestor hay una nota con la URL y la clave publicable, y la contraseña de la base de datos en otra entrada. En tu carpeta del proyecto no hay ninguna clave todavía.

    Misión 4

    Ajustes que importan

    Tres pantallas que conviene conocer desde el primer día.

    Correspondencias ↗Direcciones permitidas↗Tablas

    1 · Data API: ¿se exponen las tablas solas?

    La Data API es la «ventanilla» por la que tu web lee y escribe en las tablas. En Integrations → Data API (o en sus ajustes) hay una opción, Automatically expose new tables, que hace que cada tabla nueva sea accesible desde la API. Supabase la está cambiando para que exponer sea una decisión tuya.

    • Si está activada: tus tablas se pueden usar desde la web, siempre bajo las reglas RLS (página 07).
    • Si está desactivada: además de las reglas, tendrás que dar permiso explícito con SQL (grant select, insert on … to anon), como verás en la 07.

    2 · Authentication → URL Configuration

    Aquí se dice a qué direcciones puede volver alguien después de iniciar sesión o confirmar su correo. Viene preparada para localhost:3000, que no es la tuya. La configurarás en la página 07.

    3 · Project Settings → General

    Nombre del proyecto, pausar, reanudar y borrar. Y el identificador del proyecto (Project ID), que es la parte inicial de tu URL.

    Misión 45 minutos
    1. Busca el ajuste Automatically expose new tables de la Data API y anota si está activado o no. Déjalo como esté: en la 07 sabrás qué hacer en cada caso.
    2. Abre Authentication → URL Configuration y mira la Site URL que trae por defecto. No la cambies aún.
    3. Abre Project Settings → General y localiza los botones de pausar y borrar (sin pulsarlos).

    Misión 5

    La pausa y el segundo proyecto

    La trampa más típica del plan gratis, y cómo trabajar como en una empresa.

    Correspondencias ↗Entornos↗Costes↗Producción

    Pausa por inactividad

    Un proyecto gratuito sin actividad durante una semana se pausa. Mientras está pausado, tu web no puede leer ni guardar: las peticiones fallan (en la consola verás errores como 503 o Failed to fetch). Los datos no se pierden: se reanuda desde el panel con Restore project (o Resume), y tarda unos minutos.

    Costumbre

    La víspera de presentar o entregar un proyecto, entra en el panel y comprueba que está activo.

    Dos proyectos: pruebas y producción

    En las empresas nunca se prueba con los datos reales. Tu plan gratis permite dos proyectos activos: libro-de-visitas-pruebas (el que acabas de crear, para romper sin miedo) y libro-de-visitas (producción, el que usará la web publicada). El de producción lo crearás en la página 09, repitiendo con SQL lo que hayas hecho en pruebas.

    Misión 52 minutos
    1. Pon en tu calendario un recordatorio semanal: «Entrar en Supabase» (mientras estés con el proyecto).
    2. Localiza en Project Settings → General dónde se reanuda un proyecto pausado.

    Opcional · avanzado

    Supabase en tu ordenador

    Para cuando quieras trabajar como un equipo profesional. No lo necesitas para el manual.

    Correspondencias ↗Node.js↗Entornos

    Supabase CLI + Docker

    Supabase se puede ejecutar entero en tu ordenador: base de datos, panel y API. Hace falta Docker Desktop (un programa que ejecuta «contenedores», pequeños servidores aislados) y Node.js. Sirve para probar cambios sin tocar la nube y para guardar la estructura de la base de datos como archivos (migraciones) dentro del repositorio.

    Ojo

    Docker consume bastante memoria y en ordenadores del centro puede no estar permitido. Para este curso, el proyecto en la nube es suficiente.
