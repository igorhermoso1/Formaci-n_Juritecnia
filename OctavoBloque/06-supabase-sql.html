    Leer

    SELECT y WHERE

    «Dame estas columnas de esta tabla… pero solo las filas que cumplan esto».

    SELECT: qué columnas

    La estructura básica es SELECT columnas FROM tabla;. El asterisco * significa «todas». El punto y coma cierra la orden.

    SELECT nombre, mensaje FROM mensajes;

    WHERE: qué filas

    Filtra las filas con una condición. Los textos van entre comillas simples.

    OperadorSignificaEjemplo
    =   <>igual / distintoWHERE nombre = 'Ane'
    > < >= <=mayor, menor…WHERE id >= 5
    LIKEparecido, con comodín %WHERE mensaje LIKE '%web%'
    INuno de la listaWHERE tema_id IN (1, 3)
    BETWEENentre dos valoresWHERE id BETWEEN 3 AND 6
    IS NULLvacíoWHERE tema_id IS NULL
    AND · OR · NOTcombinar condicionesWHERE tema_id = 1 AND id > 4
    SELECT * FROM mensajes WHERE nombre = 'Ane';
    SELECT nombre, mensaje FROM mensajes WHERE mensaje LIKE '%web%';
    SELECT * FROM mensajes WHERE tema_id IS NULL;
    SELECT * FROM mensajes WHERE tema_id = 1 AND id > 4;
    En Supabase

    En PostgreSQL, LIKE distingue mayúsculas: para buscar sin distinguir se usa ILIKE. En esta consola, LIKE ya no distingue.

    Leer

    Ordenar y limitar

    Los más nuevos primero, y solo los cinco últimos.

    • ORDER BY columna: de menor a mayor (ASC, por defecto). Con DESC, de mayor a menor.
    • LIMIT n: solo las primeras n filas. OFFSET m: sáltate las m primeras (para páginas: 1-10, 11-20…).
    SELECT nombre, created_at FROM mensajes ORDER BY created_at DESC;
    SELECT nombre, mensaje FROM mensajes ORDER BY created_at DESC LIMIT 5;
    SELECT nombre FROM mensajes ORDER BY nombre LIMIT 3 OFFSET 3;

    El orden de las piezas importa: SELECT … FROM … WHERE … ORDER BY … LIMIT ….

    Resumir

    Contar y agrupar

    Estadísticas en una línea: cuántos, la media, el más largo…

    FunciónDevuelve
    COUNT(*)cuántas filas
    MIN() · MAX()el menor y el mayor
    AVG() · SUM()la media y la suma
    LENGTH() · UPPER()longitud de un texto y texto en mayúsculas (en PostgreSQL, char_length())
    SELECT COUNT(*) AS total FROM mensajes;
    SELECT MAX(LENGTH(mensaje)) AS mas_largo FROM mensajes;

    GROUP BY hace un grupo por cada valor distinto y calcula la función en cada grupo. HAVING filtra grupos (como WHERE, pero después de agrupar). AS pone un nombre a la columna del resultado.

    SELECT tema_id, COUNT(*) AS cuantos FROM mensajes GROUP BY tema_id;
    SELECT nombre, COUNT(*) AS veces FROM mensajes GROUP BY nombre HAVING COUNT(*) > 1;

    Relacionar

    Juntar tablas: JOIN

    El mensaje con el nombre de su tema, no con un número.

    Correspondencias ↗Relaciones

    JOIN pega dos tablas usando la clave foránea: «junta cada mensaje con el tema cuyo id es su tema_id». Para no confundir columnas con el mismo nombre se escribe tabla.columna.

    SELECT mensajes.nombre, temas.nombre AS tema FROM mensajes JOIN temas ON temas.id = mensajes.tema_id;

    Con JOIN a secas, los mensajes sin tema desaparecen. Con LEFT JOIN salen todos los mensajes, y el tema queda vacío si no tienen.

    SELECT m.nombre, m.mensaje, t.nombre AS tema FROM mensajes m LEFT JOIN temas t ON t.id = m.tema_id ORDER BY m.id;

    En el último ejemplo, m y t son alias: apodos cortos para no escribir el nombre entero.

    Escribir

    INSERT, UPDATE y DELETE

    Añadir, cambiar y borrar. Con dos de ellas, un olvido borra la tabla entera.

    INSERT: añadir filas

    INSERT INTO mensajes (nombre, mensaje, tema_id) VALUES ('Lucía', 'Me ha encantado', 1);

    No se envían id ni created_at: se rellenan solos. Después, ejecuta SELECT * FROM mensajes ORDER BY id DESC LIMIT 1; para ver la fila nueva.

    UPDATE: cambiar

    UPDATE mensajes SET mensaje = 'Mensaje editado' WHERE id = 2;

    DELETE: borrar

    DELETE FROM mensajes WHERE id = 3;
    Peligro

    UPDATE y DELETE sin WHERE afectan a todas las filas. DELETE FROM mensajes; vacía la tabla entera. Costumbre profesional: escribe primero el SELECT con el mismo WHERE, comprueba qué filas salen, y solo entonces cámbialo por DELETE. Pruébalo aquí sin miedo y pulsa «Reiniciar los datos».

    En Supabase

    En el SQL Editor trabajas como administrador (rol postgres): las reglas RLS no se aplican y puedes borrarlo todo. Las reglas protegen lo que llega desde la web con la clave publicable (página 07).
