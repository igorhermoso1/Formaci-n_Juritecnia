    Misión 1

    Ajustes del proyecto

    Tres pantallas de Settings que conviene revisar una vez.

    • General: nombre del proyecto (decide la dirección .vercel.app) y la opción de Directory Listing: si está activada, una carpeta sin index.html enseña la lista de sus archivos. En producción, desactívala.
    • Build and Deployment: Framework Preset (Other) y Root Directory (la carpeta donde está tu index.html; ./ si está en la raíz).
    • Git: la rama de producción (main).
    Misión 15 minutos
    1. En tu proyecto de Vercel: Settings → General. Revisa el nombre y desactiva Directory Listing si está activado.
    2. Settings → Build and Deployment: confirma Other y ./.
    3. Settings → Git: confirma que la rama de producción es main.

    Comprueba: abre tu-web.vercel.app/css/: ya no ves la lista de archivos de la carpeta.

    Misión 2

    Una página 404 propia

    Si alguien llega a una dirección que no existe, que encuentre algo útil y con tu estilo.

    Correspondencias ↗Código 404

    Vercel sirve automáticamente un archivo 404.html que esté en la raíz de tu web cuando la dirección pedida no coincide con ningún archivo. El navegador recibe igualmente el código 404 (bueno para Google: no indexa páginas que no existen), pero la persona ve tu página.

    404.html con el estilo del libro de visitas

    Una buena 404 dice qué ha pasado, no culpa a nadie y ofrece una salida: volver al inicio.

    Misión 210 minutos
    1. Crea 404.html en la raíz de tu carpeta, con estructura completa (<!DOCTYPE>, lang="es", title), el HTML de arriba y tu css/estilos.css enlazado con ruta absoluta: href="/css/estilos.css" (la 404 puede aparecer en cualquier carpeta).
    2. Añade al final de css/estilos.css el CSS de arriba.
    3. Sube los dos archivos a GitHub. Cuando Vercel publique, visita tu-web.vercel.app/no-existe.
    4. En las DevTools → Network, comprueba que esa petición devuelve el código 404.

    Comprueba: cualquier dirección inventada muestra tu página con estilo y un botón para volver, y Network marca 404.

    Misión 3

    vercel.json: la configuración en un archivo

    Direcciones limpias, redirecciones y cabeceras de seguridad, guardadas en el repositorio.

    Correspondencias ↗Seguridad↗SEO y canonical

    Si en la raíz del repositorio hay un archivo vercel.json, Vercel lo lee en cada despliegue. Es JSON: claves entre comillas dobles, valores separados por comas y ninguna coma después del último elemento.

    LíneaQué hace
    cleanUrls/privacidad.html se sirve en /privacidad, y quien entra con .html es redirigido a la versión limpia.
    trailingSlash: falseQuita la barra final (/privacidad/ → /privacidad). Así Google no ve dos páginas iguales con distinta dirección.
    redirectsManda una dirección vieja a otra nueva. permanent: true da el código 308 (mudanza permanente: los buscadores actualizan el enlace); false, el 307 (temporal).
    X-Content-Type-OptionsQue el navegador no «adivine» el tipo de un archivo: evita que un texto se ejecute como código.
    Referrer-PolicyAl pulsar un enlace a otra web, solo se envía tu dominio, no la dirección completa de la página.
    X-Frame-Options: DENYNadie puede meter tu web dentro de un iframe en la suya (evita trampas de clics).
    Permissions-PolicyTu web declara que no usará cámara, micrófono ni ubicación: aunque alguien inyecte código, no podrá pedirlos.
    Avanzado

    Existe una cabecera más potente, Content-Security-Policy, que dice exactamente de qué sitios puede cargar scripts tu web. Es muy eficaz, pero mal puesta rompe la conexión con Supabase (que se carga desde una CDN). Se ve en un curso de seguridad web.

    Misión 315 minutos
    1. Crea vercel.json en la raíz de tu carpeta con el contenido de arriba.
    2. Súbelo a GitHub y espera el despliegue.
    3. Visita tu-web.vercel.app/privacidad.html: la barra de direcciones cambia a /privacidad.
    4. Visita tu-web.vercel.app/firmar: te lleva a la portada.
    5. DevTools → Network → pulsa la petición del documento → Headers → Response Headers: ves tus cuatro cabeceras.

    Comprueba: las direcciones salen sin .html, la redirección funciona y las cabeceras aparecen en la respuesta.

    Si algo falla
    El despliegue falla tras subir vercel.json
    Casi siempre es JSON mal escrito: una coma de más al final de una lista, comillas simples en vez de dobles o una llave sin cerrar. Pégalo en un validador de JSON o fíjate en el error de los Build Logs.
    Mis enlaces internos con .html siguen funcionando
    Es lo esperado: con cleanUrls redirigen a la versión limpia. Para que sea más rápido, cambia tus enlaces a /privacidad.

    Misión 4 · opcional

    Tu propio dominio

    De libro-de-visitas.vercel.app a tudominio.es.

    Correspondencias ↗Qué es un dominio y el DNS↗Costes

    El dominio se alquila por años en un registrador (unos 10-20 € al año). Qué es y cómo funciona el DNS lo tienes explicado y animado en Súbela a internet. Aquí, el procedimiento en Vercel:

    Misión 420 minutos más la espera del DNS · opcional
    1. En tu proyecto de Vercel: Settings → Domains → Add y escribe tu dominio (por ejemplo tudominio.es). Vercel suele proponer añadir también www.tudominio.es con redirección: acéptalo.
    2. Vercel te enseña los registros DNS que debes crear (normalmente un registro A para el dominio y un CNAME para www). Copia los valores exactos de esa pantalla.
    3. En tu registrador, abre la zona DNS del dominio y crea esos registros.
    4. Espera: el DNS puede tardar de minutos a horas. Vercel marca el dominio como Valid Configuration y activa HTTPS solo.
    5. Si usas Supabase, añade el dominio nuevo en Authentication → URL Configuration (página 07).

    Comprueba: https://tudominio.es abre tu web con candado y www.tudominio.es redirige a ella.

    Si algo falla
    «Invalid Configuration» después de horas
    Revisa que los valores del registrador son exactamente los de Vercel y que no queda un registro antiguo del mismo tipo apuntando a otro sitio.
    La web va en .vercel.app pero no en mi dominio
    El despliegue está bien: es un problema de DNS o de propagación. Espera y revisa los registros.

    Misión 5

    Analítica y velocidad

    Saber cuánta gente te visita y si tu web va rápida para ellos.

    Correspondencias ↗Servicios↗Cookies y RGPD
    • Web Analytics: visitas, páginas más vistas, países y dispositivos. El plan Hobby incluye 50.000 eventos al mes.
    • Speed Insights: las Core Web Vitals (LCP, INP, CLS) medidas en los dispositivos reales de tus visitantes.

    Para una web de HTML, Vercel te da un pequeño fragmento de código con una ruta propia de tu proyecto: por eso hay que copiarlo del panel, no de un tutorial. Recuerda mencionar las estadísticas en tu política de privacidad.

    Misión 510 minutos
    1. En tu proyecto de Vercel: Analytics → Enable.
    2. Elige la opción para HTML y copia el fragmento de <script> que te enseña.
    3. Pégalo al final del <body> de tus páginas, súbelas y espera el despliegue.
    4. Visita tu web y comprueba en Network que aparece una petición de la analítica (termina en /view).
    5. Opcional: haz lo mismo con Speed Insights.

    Comprueba: pasados unos minutos, el panel Analytics muestra tu propia visita.

    Misión 6

    Revisión de calidad

    Lo que se revisa siempre antes de dar la dirección a nadie.

    Correspondencias ↗Core Web Vitals↗Validador W3C
    Misión 615 minutos
    1. Lighthouse en la web publicada, modo móvil e incógnito: rendimiento, accesibilidad, buenas prácticas y SEO en verde.
    2. Validador del W3C con la dirección publicada: sin errores.
    3. Pulsa todos los enlaces, también los del pie y la 404.
    4. Prueba la web en un móvil real y con el teclado.
    5. Comparte la dirección en un chat: la tarjeta de vista previa sale con título, descripción e imagen (Open Graph).
